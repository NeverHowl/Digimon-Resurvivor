# 디지몬 RE:서바이버 v.0.18.1 (1단계: 토대)

v0.18.0g 기준 구조 정리 패치입니다. **게임 동작, 수치, 저장 형식은 바뀌지 않았습니다.**

## 적용 (파일 3개)

기존 게임 폴더에서 아래 3개를 같은 폴더에 넣어 주세요. 나머지(`assets`, `retro_ui.js`, CSS 3종)는 그대로 둡니다.

| 파일 | 처리 |
|---|---|
| `index.html` | 덮어쓰기 |
| `patch.js` | 덮어쓰기 (6.5MB → 1.8MB) |
| `sprite_data.js` | **새로 추가** (patch.js와 같은 폴더) |

`sprite_data.js`를 빠뜨리면 게임이 시작되지 않고, 화면 왼쪽 위에 "sprite_data.js 파일을 불러오지 못했습니다" 안내가 뜹니다. 시작 화면의 빌드 표시가 `v.0.18.1 · 1단계 토대`인지 확인하세요. 이전 버전이 보이면 새로고침하세요.

## 변경 내용

1. **이미지 데이터 분리.** `patch.js` 안에 있던 PNG 205개(base64, 약 4.7MB)를 `sprite_data.js`로 옮겼습니다. 그림은 기존처럼 base64로 들어 있어 `assets` 업로드 누락이나 대소문자 문제의 영향을 받지 않습니다. 옮긴 표 9개: `V014FE_IMAGES`, `V15_SPRITES`, `V15B_IMPMON_ATTACKS`, `AGFX_DATA`, `LINE_FX_DATA`, `GAB_FX_DATA`, `METAL_MELEE_ATTACK_IMAGES`, `PAL_FX_DATA`, `BIYO_VFX_DATA`.
2. **버전 문구 한곳 관리.** `patch.js` 맨 위의 `DR_VERSION`, `DR_TITLE`, `DR_BADGE`로 제목, 빌드 표시, 런 기록의 버전 필드를 정합니다. `index.html`의 정적 제목과 BUILD 표시도 맞췄습니다. 앞으로 버전을 올릴 때 이 상수만 고치면 됩니다.
3. **누락 안전장치.** `sprite_data.js`가 없으면 위의 안내를 띄우고 멈춥니다.
4. **캐시 쿼리 갱신.** `?v=base-0181-20261102`

## 변경 위치

- `patch.js`: 맨 위(상수와 안전장치 추가), 위 표 9개의 선언부(데이터 대신 `window.DR_SPRITE_DATA.이름` 참조), `rhStart`의 `version` 필드, g 레이어의 제목/BUILD 대입 2곳. **함수 본문은 변경하지 않았습니다.**
- `index.html`: 제목, 정적 BUILD 문구, 스크립트 태그(`sprite_data.js` 추가), 캐시 쿼리.
- `sprite_data.js`: 신규.

## 확인한 범위

- 분리한 내용을 되돌리면 g의 `patch.js`와 바이트 단위로 일치합니다.
- Chromium에서 g와 새 버전을 같은 시나리오(시작 화면 → 선택 → 도감 전체 보기 → 출격 화면 → 런 8초 → 상태창)로 비교했습니다. 이미지 205/205 로드, 시작 디지몬 35, 도감 218, 출격 화면 버튼, 런 시작, 파티 표시, 화면 그리기, 상태창, 파티 진단 함수 결과가 동일하고 페이지 오류는 없습니다. 달라진 것은 제목과 빌드 문구뿐입니다.
- `sprite_data.js`를 일부러 빼고 열어, 안내가 뜨는 것을 확인했습니다.
- 확인하지 않은 것: 이 환경에는 `assets` 폴더가 없어 캐릭터 그림 3566개를 불러오는 부분은 검사하지 못했습니다(이번 변경은 이 부분을 건드리지 않습니다). 실제 Edge, 모바일 기기, 장시간 플레이도 확인하지 않았습니다.

## 직접 확인해 주세요

2. 런을 시작해 캐릭터와 이펙트 그림이 평소처럼 나오는지 (오메가몬, 임페리얼드라몬 같은 `V15_SPRITES` 폼과 아구몬/그레이몬/가부몬 이펙트)
3. 도감 전체 보기, 메모리 화면, "나의 런 기록"이 열리는지
4. 모바일에서 한 번 접속해 시작되는지
