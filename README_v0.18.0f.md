# 디지몬 RE:서바이버 v0.18.0f 핫픽스

2026-11-02 · v0.18.0e 기준 누적 패치

## 적용 방법

기존 v0.18.0 이상 게임 폴더에 ZIP 안의 `patch.js`, `index.html`을 같은 이름으로 덮어씁니다. 기존 `assets`와 `retro_ui.js`는 그대로 필요합니다. 단독 실행용 전체 게임 패키지는 아닙니다.

웹에 업로드한 뒤 Ctrl+F5로 새로고침하고 화면의 **BUILD v.0.18.0f · 파티 보호 / 기적** 표시를 확인하세요. 실행 스크립트 이름은 계속 `patch.js`입니다. 별도 버전 스크립트를 추가하지 않습니다. 기존 메모리 저장 형식과 시작 스탯은 변경하지 않았습니다.

## 기적 개편

- 이번 회차의 최근 파티 구성을 최대 3자리까지 기록합니다. 같은 종류의 디지몬도 각각 독립된 자리와 성장값으로 보관합니다.
- 각 자리는 실제 도달한 최고 진화체를 기록합니다. 같은 단계에서는 나중에 도달한 형태를 사용합니다. 아직 도달하지 않은 궁극체로 자동 진화하지 않습니다.
- 전멸 시 기록을 복사해 새 캐릭터 객체로 1회 부활합니다. 예전 사망 개체를 다시 파티에 넣지 않습니다.
- 성장·투자·패시브·장비·메모리 강화·EVO를 유지합니다. 체력 50%, E/서브웨폰/평타 쿨다운 초기화, Q 게이지 0, 2초 무적으로 복귀합니다.
- 원래 1명 또는 2명이었다면 그 인원만 복원합니다. 사망한 자리의 기록은 남지만 새 동료가 그 자리를 채우면 새 동료의 기록으로 바뀝니다.
- 판매·교체된 디지몬, 조그레스 재료로 소모된 디지몬은 복원 대상에서 제외합니다.
- 사망 후 다른 동료에게 옮긴 유물은 기존 사망자의 복원 기록에서도 제거합니다. 부활한 멤버의 유물이 보관함에 중복으로 남지 않도록 처리합니다.
- 새로운 회차를 시작하면 이전 회차의 복원 기록은 지웁니다.

## 영입 및 파티 보호

- 디지에그, 구조 알, 상점 영입, 체험장 동료 추가/교체를 공통 영입 처리로 연결했습니다.
- 중복 영입을 허용합니다. 상점의 기존 계통 제한과 문자열/캐릭터 입력 판정 불일치를 정리했습니다. 상점 상품의 추첨 규칙은 변경하지 않았습니다.
- 새 동료를 생성하는 동안 기존 멤버의 성장·투자·장비·체력·쿨다운을 별도로 보호합니다. 오류로 변경되면 원상 복구하고 정확히 선택한 자리만 추가/교체합니다.
- 알을 열거나 넘기는 과정에서는 기존 파티 구성과 보호 대상 값이 바뀌지 않도록 검사합니다.
- 이미 파티에 있는 멤버에게 신규 동료 초기화 함수를 실행하려는 호출을 차단합니다.
- 전투 중 살아 있는 기존 멤버가 승인된 변경 없이 파티에서 빠지면 원래 멤버를 복구합니다. 진화 형태·기본 계통·투자 기록의 비정상 초기화도 최근 정상 기록으로 복구합니다.
- 정상적인 피해, 쿨다운 경과, EVO 지출, 진화, 사망, 판매, 교체, 조그레스는 그대로 허용합니다. 매 프레임 체력 전체를 되돌리는 방식이 아닙니다.

## 진단 및 한계

이 패치는 원인 미상의 소실 제보에 대한 예방·복구 핫픽스입니다. 기존 제보의 근본 원인이 특정되었다는 뜻은 아니며, 모든 종류의 직접 메모리 변조를 차단한다고 보장하지 않습니다.

영입 중 오류는 해당 처리 직전 상태로 복구합니다. 전투 중 성장 기록 복구는 주기적 정상 기록을 사용하므로, 해당 기록과 오류 발생 사이에 최대 약 0.5초의 차이가 있을 수 있습니다. 피해 처리 전과 정상 진화/영입 등의 주요 시점에도 별도로 기록합니다.

보호 장치가 작동하면 원인 분류와 당시 파티 형태를 브라우저 메모리에 최대 32건 보관합니다. 서버 전송이나 개인정보 수집은 없으며 새 회차/새로고침 시 지워집니다. 문제가 발생한 직후 개발자 도구 콘솔에서 아래 명령으로 확인할 수 있습니다.

```js
digimonPartyDiagnostics()
```
