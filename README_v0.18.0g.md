# 디지몬 RE:서바이버 v.0.18.0g

v0.18.0f 기준 개체 식별·런 기록·기적 부활 보강 패치입니다.

## 적용

기존 게임 폴더의 `patch.js`, `index.html`을 이 압축파일의 같은 이름 파일로 덮어쓰세요. 기존 `assets`, `retro_ui` 등은 유지합니다. 단독 실행용 전체 게임 패키지가 아닙니다. 별도 이름의 패치 스크립트를 추가로 불러오지 않습니다.

시작 화면의 빌드 표시가 `v.0.18.0g · 나의 런 기록`인지 확인하세요. 이전 버전이 보이면 새로고침하세요.

## 개체 식별과 파티 보호

- 매 런 시작 멤버부터 #1, #2, #3 순서로 식별번호를 부여합니다. 같은 디지몬도 별도 번호를 받습니다.
- 진화와 태그는 기존 번호를 유지합니다. 영입·교체로 생긴 새 개체에는 다음 번호를 부여하며, 떠난 개체 번호는 해당 런에서 다시 사용하지 않습니다.
- 영입, 진화, 교체, 판매, 조그레스, 사망과 이탈을 시간순으로 기록합니다. 교체·판매·조그레스·실제 치명타에 따른 이탈이 확인된 경우 기존 멤버 제거를 허용합니다.
- 명령 없는 파티 삭제·삽입, 잘못된 사망 표시, 장비 변경 경로를 거치지 않은 유물 변경을 감지해 보호합니다.
- 다음 영입을 확정하기 전에 기존 성장 상태를 검사합니다. 기존 성장 초기화 보호 기능도 유지됩니다.
- 보호가 개입한 경우 런 이력에 비정상 변경 차단 내용을 남깁니다.

## 기적 부활: 동일 빌드의 새 개체

최근 파티 최대 3명의 실제 도달 최고 진화체와 성장·투자·유물·서브웨폰·메모리 강화·EVO 기록으로 새 개체를 만듭니다. 원래 개체 객체나 원래 식별번호를 다시 사용하지 않습니다.

예: `#2 파피몬 → 메탈가루몬 진화 → 사망 → 기적 부활: #2 → 새 개체 #5 메탈가루몬`

- 새 개체에 새 번호를 부여하고 원래 개체 번호와 연결해 기록합니다.
- 성장·장비 정보는 별도로 복사하며, 새 개체의 내부 소유자 참조도 새 개체를 가리킵니다.
- 기존 기적 밸런스를 유지합니다: 체력 50%, 궁극기 게이지 0, 스킬 쿨다운 초기화, 기적 1회 소모.
- 기적이 발동하면 게임오버 기록 저장창을 띄우지 않고 같은 런을 계속합니다.
- 이전 개체에 예약된 사망 이탈 처리가 뒤늦게 실행돼도 새 개체를 삭제하지 않습니다.

## 나의 런 기록

- 일반 엔딩·진 엔딩·게임오버의 대사가 끝나면 저장 여부를 묻습니다.
- `기록 저장`을 선택한 회차만 이 브라우저에 보관합니다. 메모리 강화 저장 데이터와 별도입니다.
- 시작 화면의 `나의 런 기록`에서 결과, 플레이 시간, 레벨·레이어, 함께한 개체와 마지막 빌드, 팀 변경 이력을 볼 수 있습니다.
- 유물·투자·특화·메모리 강화·진화 경로를 개체별로 확인할 수 있습니다.
- 저장 화면과 상세 화면에서 해당 기록을 JSON 파일로 내려받을 수 있습니다. 기록별 삭제도 지원합니다.
- 저장 공간 부족이나 손상된 기존 기록을 발견하면 오류를 표시하고 기존 데이터를 덮어쓰지 않습니다.
- 체험장은 정식 런 기록에 포함하지 않습니다.

이 기록은 회차 회고·버그 확인용이며 게임 이어하기 저장파일이 아닙니다. JSON 가져오기는 포함하지 않았습니다. 도중에 창을 닫은 런은 기록이 남지 않습니다. 브라우저 사이트 데이터를 지우거나 다른 브라우저·사이트 주소에서 접속하면 저장된 기록이 표시되지 않을 수 있습니다. 필요한 기록은 파일로 내려받아 보관하세요. 개인정보나 계정을 요구하지 않으며 런 기록을 서버로 전송하지 않습니다.

## 확인 범위

- Chromium에서 기존 로드·신규 계통 관련 143개 검사 통과.
- 식별번호, 중복 영입, 진화, 교체·판매·조그레스, 실제 치명타/수호자 피해 전이, 기적 새 개체·빌드 보존, 종료 저장 흐름 등 추가 21개 시나리오 통과.
- 기존 멤버의 상위/하위 진화체 영입·넘기기와 연속 보상을 조합한 30개 시나리오에서 멤버 보존 확인.
- 유물 삭제, 성장 초기화 직후 연속 영입, 잘못된 사망 표시, 명령 없는 파티 삭제의 4개 오류 주입 검사에서 복구 확인.
- 데스크톱 및 모바일 크기에서 목록·상세·저장 화면, 새로고침 후 기록 유지, JSON 내보내기 확인.
- 실제 Edge 및 모바일 기기 장시간 플레이 검증은 수행하지 않았습니다.

초기화 문제의 원인을 확정하거나 모든 가능성을 차단했다는 의미는 아닙니다. 이전 조사에서 확인한 보상창의 잘못된 뒤로가기 경로, 오래된 보상 콜백의 직접 재실행, 중복 보상창 열기는 별도 해결 대상입니다. 이번 버전은 이 상황에서 기존 파티를 더 강하게 보호하고 발생 이력을 확인할 수 있도록 하는 보강입니다. 테스트용 폴더는 배포 파일에 포함하지 않았습니다.
